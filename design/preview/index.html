Batch 01

D1 Identity and colour Accepted 16 Oct 2026

Keep Whiteboard teal (#007176 light, #5cc8c8 dark fill with dark label) as the only identity colour; neutrals move toward Apple system greys; iOS dark uses true-black grouped backgrounds. Focus ring is a separate blue so focus never reads as selection. Reason: continuity with the showcase, restraint, distinct focus. Static contrast: 63 token pairs (light, dark, iOS dark) meet 4.5:1 text / 3:1 non-text; lowest text pair 5.34:1. Rendered contrast unverified.

D2 Type Accepted 16 Oct 2026

System font stack (SF Pro on Apple platforms) with Dynamic Type roles; web body 15 px, iOS body 17 pt; tabular figures for times/scores. A “Larger text” preview (+24%) is provided; reflow at real accessibility sizes is unverified.

D3 One status vocabulary Accepted 16 Oct 2026

(K.STATUS in batch01/kit.js): Not started, Draft · not submitted, Queued · not received, Received, Not received, Feedback not released, Feedback released, Feedback updated, Excused, Locked, Closed, Extension applied, Last known, Read-only, Not open yet, Instructor preview. Always icon + words. Queued and Received never share colour/icon; Held/Not released is neutral (nothing is wrong).

D4 Navigation Accepted 16 Oct 2026

Web: sidebar (Today, Courses, Calendar, Updates; Campus: Events, Support) + top bar with Search P45 / Help P46 / Account P44, all still proposed. Narrow web collapses the sidebar to a menu and stacks columns — it stays a web page (no tab bar). Planned iOS: four tabs (Today, Courses, Calendar, Updates), account avatar in the nav bar; Search/Help placement on iOS is still open. Course sections are links (deep-linkable pages), not ARIA tabs.

D5 Preview format Accepted 16 Oct 2026

Editable sources design/system/*.css, design/batch01/*.js; node design/build.mjs embeds the S01–S09 briefs and routes from showcase/app_map/*.json and writes one offline design/preview/batch01_student_journey.html. No framework, no network assets. iPhone frames are HTML illustrations, not a native build.

D6 Truthful submission states Accepted 16 Oct 2026

Web cannot background-queue; it says so (S06 offline, S07 queued). Planned iOS may queue but shows “Queued · not received” until server acknowledgment; only then S08 “Received”. Interrupted shows “Not submitted” with no reference number.

D7 Review before send Accepted 16 Oct 2026

Scan/upload never submits; S07 confirmation restates attempt, pages and coverage. Editing a received attempt opens a copy (Attempt 2) with the original receipt preserved.

D8 Camera permission Accepted 16 Oct 2026

Pre-permission explainer, then the OS/browser prompt; denial makes Photos/Files/upload the primary path and Settings secondary.

D9 Feedback privacy Accepted 16 Oct 2026

Today/notifications say feedback exists but never show the score. Held feedback shows receipt facts only (no grading progress). Re-release names the change (old → new) and keeps the prior snapshot. Excused is distinct from zero/missing. Downstream record acknowledgment is a neutral notice that does not make released feedback look provisional.

D10 Dates Accepted 16 Oct 2026

US format with explicit time zone (“Fri, Oct 16 · 11:59 pm ET”); personal (allowance) dates lead, course dates shown secondary.

D11 Added design states Accepted 16 Oct 2026

(not new routes): S04 syllabus view, S05 choose-method sheet, S07 confirm and queued-offline. Each is labelled “added” in the preview with a reason.

Batch 03

Staff-complete reviews are “Graded · staff only” (purple/accent, check icon); learner-visible results are “Released” (green). The gradebook shows a staff calculation and a separate “Learner sees” column, so a graded-but-unreleased score never looks published.

D26 Grading workspace (S17) Accepted 16 Oct 2026

Web: roster | learner page | score/rubric/comment panel; the question selector drives all three. Three panes need ~1240 px of app width; below that the roster becomes a horizontal picker row (unverified in a browser). iOS: learner title + question picker above the page, grading in a sheet — urgent review only, not a parity claim.

D27 Rubric rule changes (S18) Accepted 16 Oct 2026

Edits are previewed as an impact table (learner, level, score now → after, effect) before Apply. Manual scores are never overwritten by a rule change. Only the instructor applies; a TA can propose (Apply disabled with reason). Applying versions the rubric (v2 → v3). Released work (PS3, v1) is listed as unchanged — this avoids, but does not settle, the open question on re-scoring released work.

D28 Gradebook statuses (S19) Accepted 16 Oct 2026

Not graded = excluded; Missing = 0 after close; Excused = removed from denominator; Graded = staff calculation only; Released = both. Each state is explained in a rail for the focused cell, with the arithmetic shown.

D29 Release (S20) Accepted 16 Oct 2026

Steps Scope → Exceptions → Preview → Release. The preview is the exact per-learner payload (attempt, receipt, score, rubric version, comments). Any change after preview makes it stale and blocks release until refreshed. Web release needs an explicit confirmation checkbox; iOS uses a final confirmation step. Post-release edits become a held draft with old → new; releasing creates a new snapshot (R2) and keeps R1 — the same records Batch 01’s S09 “re-released” state shows. Institution record acknowledgment is separate and neutral (S38 later).

D30 Quiz attempt (S10) Accepted 16 Oct 2026

Rules first: window, personal time (allowance named, separate from assignment extensions), attempts, release rule. Answers save per item; offline answers are labelled “Saved on this device · not sent” and Submit waits for a connection; the timer is described honestly (it keeps running). The submission receipt promises that questions and answers are kept together as a snapshot. Held results show no scores, keys or progress.

D31 Course conversation (S11) Accepted 16 Oct 2026

Every contribution shows name, role chip (staff chips purple) and time; the composer states who you post as and who can see it. Locked threads remove reply controls rather than disabling them. The map state “course not published” is drawn as the Module 4 discussion before it opens.

Updates link to the changed record, never show scores, and say that delivery preferences change future email/alerts only; iOS keeps system notification permission and Whiteboard delivery switches as separate controls.

D33 Handoffs and shared-kit edits Accepted 16 Oct 2026

Batch 04

D34 Course people and permissions (S21) Accepted 16 Oct 2026

Staff and students in roster tables with role, access status, end date and the action beside each person. A course-role permission table answers in words (Yes / No / Propose only / Assigned work only). It matches D27 (TAs propose rubric changes) and D29 (release is instructor-only). D35 Revocation Accepted 16 Oct 2026

Revoking access opens a review (web dialog, iOS sheet) that names the person, role, course and term. It lists what ends and what is kept, and takes an optional staff-only reason. D36 Allowances are operational records Accepted 16 Oct 2026

Each record stores what changes, which work, the personal dates or multiplier, who recorded it and when, and a basis label with at most a reference number (e.g. Accessibility Services AS-…). It never holds private or medical documentation. All course staff see the adjusted timing; only the instructor sees the basis reference. S17’s Excuse/Extension buttons now open S21. Tomás Rivera’s PS4 extension (recorded Mon, Oct 19, after S17 showed him Missing) is the sample. The route to S15 shows the personal date in the assignment editor.

D37 Course copy (S22) Accepted 16 Oct 2026

The steps are Select → Dates → Preview → Copy. A “Never copied” list names the learner data that is excluded: people, submissions, scores and feedback, discussions, allowances and attendance. Dates shift by a stated rule (+21 weeks, weekdays kept), and source and destination dates sit side by side. Dates that land in a break are flagged for checking, not moved silently. An unsupported external tool blocks the copy until the instructor picks a placeholder page or leaves it out. “Approved tool” is shown as unavailable, with who reviews tool requests. The copy needs an explicit review checkbox on a current preview, and any change makes the preview stale. Applying creates a separate draft course with zero learners and leaves the source unchanged.

D38 Insights are facts, not predictions (S23) Accepted 16 Oct 2026

The page shows three separate records: not submitted before close (named, with allowance status; excused learners not counted), module completion (three named counts) and attendance (each entry with its source). There is no composite score, risk label or prediction. An attendance correction quotes the request and records the corrected status, reason, who and when. The original entry is kept in history. When a source is delayed, entries are labelled “last known”, and an unentered session is not counted as absent. Referral to advising (S35) is a handoff.

D39 Scheduling-office shell and timetable (S24) Accepted 16 Oct 2026

The new shell has Timetable, Change reviews and Find a room (S26, later). The role and term are shown, and iOS gets matching tabs. The timetable is a read-only copy of the institution scheduling source, with the system, status and last refresh always visible. Conflicts attach to the specific meeting, with text and evidence (a Facilities notice). Proposals appear inside the meeting as dashed “Proposed · not applied” notes while the source room stays shown. A department scheduler (e.g. Dr. Diane Reyes for Physics, from P41/P43) is assumed to see the same page filtered to their department and to propose but not approve. That scope is an assumption to confirm.

D40 Approve ≠ apply (S25) Accepted 16 Oct 2026

Each room option shows its constraint verdict, and rejected alternatives stay visible: a room that is too small, and one that overlaps another class. A constraint evidence table compares current and proposed. Submitting and approving are both stated not to change the timetable. Apply source copy is a separate, acknowledged step. The change counts as “Applied” only when the refreshed source copy reflects it. Learners hear about it through Calendar (S12) only after that point, as a handoff. The MATH 220 move to Keene Center 105 (applied Thu, Oct 15 · 7:30 am) is the same change S12 shows learners at 7:40 am.

Batch 05

D42 Campus navigation Accepted 16 Oct 2026

The student web sidebar’s Campus group becomes Events (S28), Organizations (S29) and Support (S34, later). D43 Room search checks the whole interval (S26) Accepted 16 Oct 2026

Every result repeats every requirement as met or not met, in text, and states its availability for the full start-to-end interval, including setup and teardown. Unavailable rooms stay listed with the conflicting booking named. Requirements are never dropped to find a match; “No full match” explains what each closest option lacks. Choosing a room is not a request.

D44 Request ≠ approval ≠ confirmation (S27) Accepted 16 Oct 2026

A request moves Draft → Requested → Approved · not confirmed → Confirmed in source. Approval records a fingerprint of the exact details, and any change to them returns the request to review. Confirmation is a separate step: the approver records the reservation system’s confirmation number, and Whiteboard never books a room. A single date is cancelled on its own and the series is kept. Calendar shows the request with the same status words (new S12 requester state).

D45 Participation status (S28) Accepted 16 Oct 2026

Place confirmed, Full, Waitlisted (#n of m) and Cancelled are text badges on every row and in the details. Capacity is a sentence (“48 of 60 places confirmed · 12 left”) before the bar. A waitlist position creates no pass and no calendar entry. Cancelled events stay visible to people who held a place, with who, when and why, and their actions are removed. Only approved, published versions appear in discovery.

D46 Organization ownership (S29, S30, S33) Accepted 16 Oct 2026

Drafts, room requests, funding requests and files belong to the organization, never to an officer’s account. A revision is an organization draft beside the unchanged published version. Capacity can’t drop below confirmed places. “Send for review” needs valid fields and every dependency at least requested. The handoff needs an assignment, the incoming officer’s acceptance and every required item done. Until then the outgoing officer stays in the role. Afterwards the outgoing officer keeps membership and the organization keeps the work.

D47 Independent dependency owners (S31) Accepted 16 Oct 2026

Room (Event Services), funding (Student Activities Fund) and event review (Student Activities) each show their owner and status. A reviewer can read the room and funding decisions but can’t change them. An open dependency disables Approve, naming that dependency. Approve ≠ publish: approval fingerprints the revision; publishing replaces version 1 and notifies the confirmed attendees.

D48 Offline check-in is not attendance until synced (S32) Accepted 16 Oct 2026

Check-ins made offline read “Queued on this device · not synced”, and the event total counts synced records only. Reconciliation shows each queued record’s result. A duplicate keeps the earlier check-in and names the device and time. An ineligible result gives a reason and what to say, with no operator override. Operator scope is one event for a set time. Manual lookup covers a denied camera.

D49 Student pass (added S32 state) Accepted 16 Oct 2026

The pass shows a decorative code, a short typed or spoken code as its accessible equivalent, and the event, time, place and status. It works offline and needs no calendar permission. Wallet is out of scope.
