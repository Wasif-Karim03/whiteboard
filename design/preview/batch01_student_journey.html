Student course → submission → feedback

A proposed shared design system and the first coherent journey, S01–S09, drawn for desktop web, narrow web and a planned iPhone app. Content, roles, states and routes come from the navigation atlas (showcase/app_map), embedded at build time.

Pick a state above each pair of frames. Primary actions inside a frame move through the journey; other controls explain where they lead. Add #S07:incomplete to the address to open a state directly.

What this is — and isn’t

  • Design review draft. Not owner-accepted.
  • All people, schools, courses, scores and receipts are fictional.
  • Web frames are concept designs; P-numbered screens are proposed destinations. iPhone frames are HTML illustrations of a planned iOS app; no native build exists.
  • No sign-in, identity provider, upload, storage, grading service or live integration exists. URLs use the reserved .example domain.
  • Browser, keyboard, screen-reader and device checks have not been run. Only static source checks have.

Journeys and recovery paths

The receipt ends the student submission. Grading and release are separate staff actions; a dashed handoff never grants the student staff access.

Proposed · not accepted

Restrained and system-native: SF Pro, generous whitespace, one teal identity colour, semantic status that never relies on colour alone. Web and iOS share tokens and status language; navigation and layout follow each platform’s conventions.

Icon + words, never colour alone. ‘Queued · not received’ and ‘Received’ never share a colour or icon. ‘Feedback not released’ is neutral, not a warning — nothing is wrong.

Actions

  • One primary action per view region.
  • Unavailable actions stay focusable and are described by their reason.
  • Web hit target ≥ 32 px (24 px WCAG 2.2 minimum); iOS ≥ 44 pt.
  • Consequential actions (submit, release) confirm with the exact facts.

Spacing, shape, motion, focus

  • 4-pt grid: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 56.
  • Radii: controls 8, inset groups 10, cards 12, sheets 16.
  • Elevation: one soft card shadow; modals add scrim. No gradients.
  • Motion 120–320 ms ease-out for state changes only; none under Reduce Motion.
  • Focus: 3 px blue ring, 2 px offset, on every interactive element.
  • Light/dark from system preference with a manual override; iOS uses true-black grouped backgrounds.

Contrast · static token math

63 token pairs across light, dark and iOS dark: all meet target. Lowest text pair: light 5.34:1, dark 5.96:1, iOS dark 6.41:1.

Colour arithmetic only. Rendered contrast, forced colours and screen-reader output are not yet verified.
