## 2. Must fix before freeze

### M1 (severity 3). Pages get a role but no person or course

- **Where:** `viewer/compose.js:88-92`, `pages/PAGES.md:38`, `fixtures/world.js:18-36`.
- **Problem:** `render(a)` receives `role` only. Nothing maps a role to a person. The scoped selectors need `who = {role, personId}` (`receiptsFor`, `reviewProgress`, `taTaskAccess`), so every page must hard-code "aisha", "maya", "reyes" and "phys110-f26" and build `who` by hand. `receiptsFor` trusts that pair: `{role: "instructor", personId: "maya"}` returns both PS4 receipts.
- **Fix:** add one persona map to the world fixture and a selector `viewerFor(view, role)` that returns a frozen `{role, personId, courseId}` with the role read from the enrollment. Have the composer pass it as `a.who`. Add a selector that returns the shell `course` option (tabs and tools as `{id, label, go, current}`) from `courseNav` and `staffTools`, which today return `{id, label, page}` that no shell accepts.

### M2 (severity 3). Release authority is not enforced anywhere

- **Where:** `fixtures/staff.js:96-101` (`releaseReady`), `fixtures/grades.js:139-144` (`releasePreview`), `fixtures/staff.js:19` (`release_permission`), `manifest/pages.js:73`.
- **Problem:** W53 lists `ta` in its roles, so the composer does not block a TA. `releaseReady` and `releasePreview` take no viewer and return the candidate list and the 84.50% → 85.17% preview to any caller. No selector reads `release_permission`. The only guard, `check_authority`, is a Phase 4 stub. "A TA cannot release or preview a release" currently depends on each page author remembering it.
- **Fix:** give both selectors a `who` argument and return null unless the viewer is an instructor of that course. Add `canRelease(view, who, courseId)`. Assert in `check_fixtures` that Maya gets null from both at the default clock.

### M3 (severity 3). Progress, grade and calendar selectors fail open

- **Where:** `fixtures/staff.js:62-72`, `fixtures/grades.js:96-99,122,129`, `fixtures/calendar.js:41-50`.
- **Problem (each confirmed by running it):**
  - `reviewProgress` and `receivedProgress` restrict only when `who.role` is "ta". A student, a guest or no viewer at all gets the class-wide counts (`{reviewed: 1, of: 2}` for Ben as a student).
  - `draftTotal` takes no viewer. It returns Aisha's held 27/30 at the `ta_expired` clock and to a student.
  - `courseTotal` lets the caller choose `audience: "staff"`, which returns the unreleased 85.17%.
  - `eventsFor` trusts a `role` argument: Ben passed as "instructor" sees Maya's grading-due task. With no role it returns course events.
- **Fix:** take `who` from M1 everywhere and allow by list: instructor of the course sees all, a TA sees the task scope while access is active, anyone else gets null or the learner's own released view. Derive the grade audience from `who`. Change `eventsFor(view, personId, role, from, to)` to `eventsFor(view, who, from, to)`. These are signature changes, which is why they cannot wait.

### M4 (severity 3). No selector for a result row, a grade draft or the gradebook

- **Where:** `fixtures/grades.js:42-58` (records), `:96` (`countedItems` is private).
- **Problem:** W23, W24, W49 and W51 need per-item values. The only route is reading `view.data.grades.results` directly, where the unreleased `pending` value sits beside `released` in the same record, and `grade_drafts` with marks and the comment. A student page is one property name away from a held score. `a.view` is the whole data set for every role.
- **Fix:** add `resultFor(view, personId, itemId, who)` (learner gets the released snapshot only), `gradeRows(view, courseId, personId, who)`, `gradeDraftFor(view, personId, assessmentId, who)` and `gradebook(view, courseId, who)`. State in PAGES.md that pages never read `view.data.grades` or `view.data.staff`, and add a source check that fails a page file containing `.pending` or `grade_drafts`.

### M5 (severity 3). Fixture records the spine needs do not exist

- **Where:** `fixtures/` (searched for release, rubric, module, draft and request records: none), `fixtures/scenarios.js:42-51,163`.
- **Problem:**
  - No release snapshot record (time, actor, version, released comments). W23 cannot draw "Released", W24 cannot show a last release time, W53 has no history. Immutable release snapshots are a core product truth with no record behind them.
  - PS4 is held in all eight scenarios, so J03 cannot reach its ending (W23 and W24 showing 85.17%).
  - No draft payload. In `assignment_submission` the receipt is projected out and the draft submission carries no files, pages or tags, so W20 and W21 have nothing to list.
  - Failure states need data too (two competing score revisions for W49, the stale preview for W53), but PAGES.md forbids typing a figure or date into page text.
  - Thin data: Ben and Carmen have no results for PS1–3, the lab or Quiz 2, so two of three W51 rows are blank; PS4 has no prompt, attempt limit, late rule or open date for W19; there is no module for W14's "current module".
- **Fix:** add release snapshots, a `ps4_released` scenario (with a golden check that the learner total is 85.17% there), a PS4 draft record, PS4 assignment facts, one module, PS4 rubric criteria with per-question comments and a reviewer and time on the draft, sample records for the failure states, and results for Ben and Carmen. Other datasets are also absent (regrade request, invitation, attendance, files, question bank); treat the freeze as "existing records and selectors do not change; additions go through the coordinator".

### M6 (severity 3). No layout primitives, and pages may not add CSS

- **Where:** `system/components-*.css` (no stack, grid, columns or rail class), `system/shell-web.css:46`, `pages/PAGES.md` "Kit changes", `tools/html_check.mjs:32-85`.
- **Problem:** the only layout tools are the vertical gap on `.wb-main` and `K.split` (list and detail). W14 needs an overview plus a context rail, W19 a status rail, W24 a row of figures, W49 three regions. Pages cannot add CSS, and `checkHtml` neither forbids nor sanctions a `style` attribute (the CSP allows it). Six builders will either file the same kit request on their first page or each invent inline styles.
- **Fix:** add `K.stack`, `K.grid` and a main-plus-rail component that take the ctx, with their CSS. Add a `checkHtml` rule that rejects `style=` outside the kit.

### M7 (severity 3). No anchor record per page, and tours carry no scenario

- **Where:** `kit/core.js:58-61` (`go` is a page id plus an optional token), `manifest/journeys.js:9-16`, `viewer/tours.js:25-30`, `pages/PAGES.md`.
- **Problem:** routes have parameters but links do not, and the contract never says which record a page draws (W19: PS4 or the group assignment; W49: Aisha or Ben) or what the eight W18 rows link to. Segments 2, 3 and 6 link to each other and will choose differently. A journey step fixes page and role only, so the J02 tour at the default clock opens W20 and W21 for PS4 two days after it closed and five days after it was received.
- **Fix:** add a table to PAGES.md: page, anchor record, home scenario, and the variant ids for other records (for example `W19:motion`). Add a `scenario` field to journey steps and apply it in `tours.viewFor`. State that a row with no drawn destination is plain text, not a link.

### M8 (severity 3). The contract has no TA-scope section, and staff spine tiers are unclear

- **Where:** `pages/PAGES.md` (no mention of `who`, grading tasks or access end), `tools/page_meta.mjs:48,68`, `kit/adaptive.js:179`, `fixtures/scenarios.js:107`.
- **Problem:**
  - Nothing tells a builder to use the scoped selectors or what a TA page shows after access ends. The `ta-expired` failure names W48, W49 and W05 only, yet W14, W18, W19, W51 and W53 also allow a TA and `check_render` renders them at the `ta_expired` clock.
  - W53 on iPad is tier `full` but its note says "review only". `K.handoff` throws on the full tier, so there is no sanctioned way to draw it.
  - W48, W49, W51 and W53 on iPhone are tier `review` with the default note, which names no protective action. PAGES.md says to draw "the protective actions its tier note names".
- **Fix:** add a "Roles and scope" section (pass `a.who`; TA pages branch on `taTaskAccess` and `taAccessActive`; the exact content after access ends; a TA on W53 sees own completion status only). Add one row per staff spine page for iPad and iPhone naming what is drawn and which protective actions exist.

### M9 (severity 2). The iPhone shell drops staff course tools

- **Where:** `kit/shell-iphone.js:23-29,40-48`.
- **Problem:** web and iPad render `course.tools`; the iPhone shell renders tabs only. Rendered as a TA with a "Grading plan" tool, the iPhone frame does not contain it. W39, W43, W46, W54 and W57 are then unreachable from course navigation on iPhone, and builders will add in-body links to about 25 staff pages to pass `check_reach`.
- **Fix:** add a "Course tools" list to the iPhone section menu for instructor and TA, with a kit test.

### M10 (severity 2). The contract does not say how a committing action is drawn

- **Where:** `kit/core.js:80` (`WB.ACTS`), `pages/PAGES.md` "Data, interaction and links".
- **Problem:** Submit (W21 → W22) and Release (W53) both change a record and move on. The contract offers a button that does nothing, or a link. It does not say which, so the spine's two key moments will be drawn differently per builder.
- **Fix:** decide once and write it down. Suggested: a button opens the confirm dialog; the dialog's primary item is a destination to the result page in the scenario where the record exists (`W22`, or `W53` in `ps4_released`).

## 5. What is sound

- Views are deep-frozen and resolved per scenario; projection removes anything dated after the clock.
- `receiptsFor` scopes correctly for a real TA: Maya gets only her two PS4 receipts, nothing after 25 Oct, and a group receipt only when every captured member is in scope.
- The status bridge keeps Graded and Held away from students: both map to "Received · Feedback not released yet", and `K.status` throws if a page asks for a word the role may not see.
- Learner arithmetic reads released snapshots only; the golden numbers are computed from records.
- Kit ids are caller-supplied and namespaced; `check_render` checks uniqueness across bar, chrome and frames.
- Each shell renders one `<main>`, one `<h1>` and labelled navigation; hit targets follow a per-shell token (24 px web, 44 pt iOS); disabled buttons stay focusable with a visible, linked reason.
