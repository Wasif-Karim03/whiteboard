Reading the atlas

A map of the intended product.

How to follow a route

Choose a journey, select a step, then inspect “Comes from” and “Goes to.” Each connection names the action and any condition. The complete directory includes alternate paths beyond the guided journeys.

Screen IDs are stable reference labels. A screen is a destination or workspace; dialogs, themes, loading states and role variants do not create extra counted screens.

Responsibilities stay separate

Students see their own learning and requests. Instructors and assigned TAs work within course permissions. Registrars, student affairs, advisors and IT receive role-specific workspaces. Following a map link never grants access.

Identity providers govern sign-in. The SIS governs official enrollment and records. Room authorities confirm bookings. Sensitive support notes stay restricted. Finance and other specialist systems remain integration boundaries.

What exists, what is planned

The existing showcase is a visual product concept. Ten additional destinations cover access, onboarding, account tools, search, technical help, content/files, reusable rubrics and institution setup.

No live institution deployment, native iOS build, production integration, AI inference or security certification is implied. Schematic screen layouts explain structure; they are not finished native UI designs. The map is a proposed navigation contract and needs implementation and usability validation.

iPhone scope

All 50 destinations are represented so the whole product can be understood on a phone. Twelve dense staff workspaces recommend web authoring or bulk work. Phone review and handoff are mapped; native parity is still a design decision.

Dates, people, courses and event examples are fictional. This file runs offline and does not send data or perform the mapped product actions.
